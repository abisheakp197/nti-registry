NTI Registry Documentation

Endpoints

MethodPathPurpose
POST/api/registerSubmit a signed entry
GET/api/listFull list of entries
GET/api/verify?id=...Verify one entry
GET/api/search?q=...&category=...Filter entries
GET/api/statsPublic counters
GET/api/healthHealth check
GET/api/federationFederation manifest
POST/api/federation/registerRegister a peer registry
GET/api/sync?from=...Pull entries from a peer

Why Cryptographic Proof

Existing registries let anyone claim anything. This registry requires:

  • Dilithium5 signature by the tool owner
  • Hash integrity (SHA-256 over canonical JSON)
  • Cross-verification against a live badge node

Federation

Any organization can run their own registry node. Two nodes sync by:

POST /api/federation/register
{ "url": "https://peer.example.com", "name": "peer-name", "kind": "registry" }

Then pull entries from a peer:

GET /api/sync?from=https://peer.example.com

Neutrality

No central authority. No silent edits. Every entry is signed. Every change is a new entry. Registry operators do not vouch for entries — they only forward signed data.
